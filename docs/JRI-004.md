## Actual hybrid comparison

The local CPU matcher reran all 16 frozen queries and reproduced the original
whole-photograph top-five reference IDs/scores to eight decimal places. Expanded
search combines reviewed manual transcription and pictorial leads with crop visual
rankings over every eligible indexed record. It does not perform automatic OCR.
An exact distinctive inscription explicitly reported by a source can support a
**CANDIDATE** research recommendation; it does not require independent authentication
of the historical reference. Matching names, descriptions or filenames alone do
not become literal inscription evidence. Generic material/origin terms and lone
initials cannot identify makers. Partial letters can retrieve prefix leads without
being treated as complete lettering or hard contradictions.

The comparison produced **2 source-supported candidate leads / 14 UNKNOWN**.
One is based on a source-reported surname stamp; the other on a source-reported
initial-plus-surname stamp. Neither is an identified owner piece. A high-scoring
trade-post reference is downgraded when the query's complete surname contradicts
its visible lettering. A related surname/monogram directory entry with conflicting
caption/alt text remains a lead, not a supported match. Generic STERLING plus one
initial, unresolved two-letter initials and uncertain pictographs remain UNKNOWN.

The contradiction penalty is a transparent fixed ranking rule; the adjusted score
is neither cosine nor probability. Raw cosine is still displayed. Pictorial or
unreadable references are not rejected merely for lacking readable letters. The
old visual ranker continues returning diagnostic neighbours; the directory hybrid
never assigns a maker solely from that ranking.

**No measured identification improvement, precision, false-match or unknown-maker
rejection rate is claimed.** All evaluation maker identities and upstream camera
provenance remain unverified. The targeted acquisition used the visible benchmark
leads, so this is a research comparison rather than an untouched confirmatory test.
The original six-case source-family baseline is not directly comparable. Further
progress requires eligible reference-photo comparisons, independent source
corroboration, documented owner identities and genuinely independent positive and
confusing-negative photographs. LoRA remains unauthorized and unjustified.

The self-contained local HTML comparison shows each query/crop beside original
visual matches, source-linked text leads, raw cosine, explicit contradictions,
missing evidence and CANDIDATE/UNKNOWN. It embeds only private local query and
previously eligible reference previews. External-only new images remain deliberate
links. CSP blocks remote resources/scripts. The HTML, annotations, JSON results,
source reviews, database, page snapshots and backups are ignored private data.

## Three comparable ranking approaches

`radar.references.owner_evaluation` freezes all three approaches against one
eligible reference snapshot and the same query pixels:

- **Visual:** the existing pinned local ResNet-18 representation and cosine ranking.
- **Text:** human-assisted transcription of reliably legible inscription text,
  normalized for Unicode/diacritics, case and punctuation. This is not automated
  OCR and must not be advertised as image-only recognition. Partial/unreadable
  transcripts are ignored. Candidate names, filenames, expected identities and
  mark descriptions are never substituted for visible inscription text.
- **Hybrid:** a fixed, untuned 50/50 mixture of rescaled visual cosine and normalized
  text agreement. Component scores are shown separately; neither is a probability.

Reference text is used only when its existing mark record says LEGIBLE. Generic
composition/origin words (`STERLING`, `SILVER`, `COPPER`, `925`, `MEXICO`, `TAXCO`,
etc.) and ambiguous short initials do not provide distinctive maker evidence.
Fuzzy text agreement may rank suggestions, but a CANDIDATE decision requires exact
informative legible-token support for one attributed family, with no conflicting
family or insufficient-image-quality flag. A visually plausible score alone is
never enough. No alias inference turns `R.B.` into Running Bear, or one Yazzie
into another. A matching `BELL` inscription supports inspecting a reference; it
does not establish Bell Trading authorship against all possible makers worldwide.

Every result can be **UNKNOWN**, while still showing possible source-linked marks
for human inspection. **Visual-only defaults to UNKNOWN for all queries** because
no independent acceptance calibration exists. This deliberately has zero candidate
acceptance coverage; its perfect rejection of unknown controls is not recognition
success. Text and hybrid use a provisional evidence rule, not a validated detector.
`CANDIDATE` means an attributed reference worth reviewing, never authentication,
material verification or a financial action. The original JRI-003 similarity CLI
remains a diagnostic ranker; use this separate owner-evaluation workflow for
explicit abstention and blind comparisons.

## Supplying private independent photographs

Use sharp, original photographs of the actual piece: one close-up of the maker
mark and one wider reverse/context view binding that mark to the same object.
Photograph parallel to the surface under diffuse light and try several lighting
angles when glare obscures letters. Avoid digital zoom, AI enhancement, added text,
screenshots and gallery copies. Keep originals privately. Accepted intake formats
are JPEG/PNG/WebP under the existing validation bounds (20 MiB / 25 megapixels).

All views of one physical object share an anonymous `capture-group`. Different
lighting shots are not independent physical objects. Calibration and evaluation
must use different object groups; the intake refuses crossing those partitions.
Do not infer missing letters from a believed maker. If only STERLING is readable,
transcribe only STERLING and expect UNKNOWN. If a mark cannot be reliably read,
leave the transcript blank and select PARTIAL or UNREADABLE.

The evaluation root defaults to **`data/jri-evaluation/`**, separate from
`data/jri/` and all training/reference exports. Source files are left untouched;
intake keeps oriented, metadata-scrubbed pixels and their source/full/crop hashes.
It stores no evaluation image in SQLite and imports no photo into the reference
index. Provenance is an owner declaration, not forensic proof of an independent
camera capture or verified artist identity.

```bash
# Photo must already be supplied privately; this example file does not exist yet.
.venv/bin/python -m radar.references.owner_evaluation intake data/private-photo.jpg \
  --capture-group piece-a --provenance 'Owner original photograph, capture session A'
```

The response returns a new case ID. Open its private
`data/jri-evaluation/cases/CASE_ID/full.png` preview. Choose the hallmark box in
**that normalized preview's coordinates**, which may differ from the original
file's EXIF orientation/resolution. The preview is at most 1600 pixels. Then make
an append-only correction using the original photo, a real box and only legible
text (replace the coordinate placeholders):

```bash
.venv/bin/python -m radar.references.owner_evaluation intake data/private-photo.jpg \
  --capture-group piece-a --provenance 'Owner original; manually reviewed mark box' \
  --box X0 Y0 X1 Y1 --legibility LEGIBLE --transcription 'STERLING' \
  --supersedes CASE_ID
```

Corrections get new case IDs; previous photographs/annotations remain intact and
are superseded for later runs. Tiny boxes are padded for diagnosis without
inventing detail and flagged LOW_RES_MARK, forcing UNKNOWN. Do not erase/inpaint
watermarks or modify the historical source photographs. Existing source-composited
insets are flagged controls, not independent reverse photographs.

Intake refuses reference-derived exact/canonical pixels, duplicate captures without
an explicit correction, reference-nested evaluation roots and partition leakage.
A **hash-only append-only exclusion register** in the reference root blocks owner
query pixels from reference ingestion, crop creation, indexing and export even if
someone later tries to import them. The register contains no photo or expected
maker label. These guards address supported workflow and exact/canonical reuse;
they cannot prove independence of arbitrary re-encoded or rephotographed copies.
Manual provenance and capture-group review remain necessary. Future training must
never consume this holdout directory or promote these test photographs.

## Freeze before opening labels

With the optional local similarity dependencies and pinned weights already
installed, freeze queries against the unchanged reference index:

```bash
.venv/bin/python -m radar.references.owner_evaluation freeze
```

The returned run ID and SHA-256 identify immutable `runs/RUN_ID/run.json`. Each run
records query/case hashes, model revision, reference-index digest, policy and
implementation digest. Labels are not an input to ranking. Keep that digest before
opening expected identities. The human transcript must describe visible text,
not a post-hoc guess based on those identities.

Create a separate private labels JSON **after** freezing, using actual case IDs:

```json
[
  {
    "case_id": "REPLACE_WITH_RETURNED_CASE_ID",
    "target": "UNLABELLED",
    "expected_family": null,
    "evidence": "Record attribution evidence and its limits; no inferred maker from STERLING"
  }
]
```

Use KNOWN with a supported expected family, UNKNOWN for a genuinely out-of-library
or unidentified family, or UNLABELLED when evidence is insufficient to score.
A known piece with an unreadable photograph is still a known-identity, low-quality
case: abstention reduces known-query coverage and must not be relabelled as a
successful unknown-maker rejection. Owner beliefs and gallery attributions are not
independently verified gold labels; record their scope honestly. Source family
names normalize punctuation/case only and must match the snapshot's attributed
families. Missing library coverage is a separate limit, not a licence to invent a
reference or infer a maker from initials.

```bash
.venv/bin/python -m radar.references.owner_evaluation score \
  data/jri-evaluation/runs/RUN_ID/run.json data/private-labels.json \
  --run-sha256 THE_RECORDED_DIGEST
.venv/bin/python -m radar.references.owner_evaluation report \
  data/jri-evaluation/runs/RUN_ID/run.json CASE_ID data/private-results.html \
  --run-sha256 THE_RECORDED_DIGEST
```

The private HTML report embeds scrubbed query/reference pixels, shows source links,
attributed candidates, mark descriptions, component scores and UNKNOWN reasons.
It escapes metadata, blocks remote resources/scripts with CSP and refuses overwrite.
No third-party image transfer or hosting is needed or performed. This task made no
new Page/backup upload; evaluation material remains local and separate.

Metrics include raw top-one/top-five matching families, incorrect maker suggestions,
incorrect **accepted** candidates, unknown abstention, known-query candidate
coverage and physical capture-group counts. An approach returning UNKNOWN for
everything cannot be presented as a useful success based on rejection alone.
Control and owner origins, calibration/evaluation partitions and crop conditions
are stratified rather than pooled. Future independent ranking winners are reported
descriptively; the software does not declare reliability or statistical improvement
from a small sample. Use separate untouched evaluation data before tuning any rule.

## Actual local control results

Before the new package arrived, the separate control experiment ran
**27 gallery-derived controls and zero supplied evaluation photographs**: 17
reference-record family holdouts (six with matching-family references remaining,
11 with that family withheld) and ten repeated-inset queries from five source
objects. Bell, Atkinson, Maisels and Running Bear are included. These are not new
independent photographs, verified maker negatives or an authentication benchmark.
Reference-derived controls never enter the owner intake/quarantine as owner data.
Query item/parent asset and exact query hashes are excluded from retrieval.

| Tight query + tight references | Known family queries | Top one | Top five | Candidate acceptance coverage |
| --- | ---: | ---: | ---: | ---: |
| ResNet visual | 6 | 3/6 (50%) | 4/6 (66.7%) | 0/6 |
| Human-assisted legible text | 6 | 3/6 (50%) | 3/6 (50%) | 3/6 |
| Hybrid | 6 | 3/6 (50%) | 4/6 (66.7%) | 3/6 |

Visual and hybrid raw rankings are **unchanged from the prior six-case baseline**.
Among known-query top-five slots they returned 23 wrong-family suggestions out of
30; text returned 14 out of 20 slots. All approaches abstained on all 11 held-out
singleton-family controls, with zero incorrect accepted candidates. Visual did so
by abstaining universally; text/hybrid accepted only three distinctive-text cases.
These control counts cannot estimate independent unknown-maker false-accept rates.

The paired crop/context ablation freezes all four combinations, with no watermark
erasure or index mutation. On ten **correlated repeated-inset** queries:

| Query region / reference region | Visual top one / top five | Hybrid top one / top five |
| --- | --- | --- |
| Tight mark / tight mark | 9/10 / 10/10 | 9/10 / 10/10 |
| Full gallery layout / full gallery layout | 8/10 / 10/10 | 8/10 / 10/10 |
| Full gallery layout / tight mark | 1/10 / 5/10 | 3/10 / 7/10 |
| Tight mark / full gallery layout | 0/10 / 2/10 | 2/10 / 4/10 |

Text gives 2/10 top-one and top-five in every combination because only the legible
Shakey insets supply distinctive usable text under this strict rule. Cropping on
both sides helps one case relative to full layouts in this small control set;
mismatched query/reference representations are much worse. Shared jewelry layouts,
watermarks and repeated insets confound the result. It does not establish an
independent-photo benefit or isolate watermark causality. The six family holdouts
are isolated mark references already, so their scores do not change with cropping.
No crop setting, hybrid weight or threshold was tuned to these results.

## What is needed before considering specialized training

First supply genuinely independent sharp mark/context photographs and unknown-maker
controls. The two intended pieces provide only two physical object groups, even
with many views. Include distinct objects, acquisition/camera sessions, glare,
rotation, wear, partial marks, generic composition stamps and confusing different
makers. Establish independent label evidence and adequate eligible references for
missing maker families; never resolve one maker merely from another's surname.

Keep calibration objects, final evaluation objects and any future training objects
separate, including same-object views and near duplicates. Measure uncertainty at
the object level, known-query coverage and false accepts on truly unseen unknowns.
More training data cannot substitute for missing labels, missing reference coverage
or a frozen independent test. No LoRA is approved here. Art-Amerindien's current
review permits local matching only, **not training**; any future training corpus
requires a separately permitted source/owner basis. This PR does not collect,
upload or train on images and does not alter Haiku, financial or historical runs.
