## Extraction and workflow boundaries

The existing MIME importer dispatches narrowly to observed source structures.
Inert HTML ancestry keeps each card's title, amount and seller together.
Unresolved linked cards remain structural boundaries. Ambiguous message-wide
fields stay in the raw evidence instead of being assigned to another lot. Supported
identities are Invaluable's global ten-character lot code and LiveAuctioneers'
numeric item ID. A mutable title slug, local lot number, catalog or tracking token
is never substituted for a global lot identity. Catalog identity remains separate.

Offline locator recovery accepts only these observed structures:

- An official Invaluable lot/catalog URL explicitly present in a tracking anchor's
  title attribute. The opaque `qs` value is never decoded or followed.
- A LiveAuctioneers tracking path containing an explicit base64url target.
- The observed LiveAuctioneers JSON/base64 wrapper with an explicit inner URL.

Targets must be official HTTPS item/catalog paths. Off-domain, credential-bearing,
unsupported-port, traversal, ambiguous and unsupported wrappers remain unresolved.
No HTTP requests, active HTML, email resources or attachments are executed.
Unresolved evidence remains in the private original message for owner review.

Source registration, overall message type and each lot's query relationship are
independent. `reviewed_email_formats` references the specific reviewed structures;
global source verification alone cannot validate a new template. Synthetic,
recommended and sponsored cards do not gain saved-search success credit. A real
saved-search card requires both exact query evidence and its format review.

The source registry is additive. Existing custom entries with the official platform
domain keep their IDs, names, settings and histories, and are used by parsing and
Auction research. An audit of four existing application databases found no earlier
entries for these two platforms. New canonical entries were added only in the
isolated pilot. Duplicate platform registrations are rejected on both creation and configuration
edits; an ordinary save excludes its own source ID from that check. JRI-009's 65 exact
catalog phrases and 15-phrase starter view are available for each source; existing
owner choices remain unchanged and no external search is configured automatically.

Auction research retains the earlier source precedence, then Invaluable and
LiveAuctioneers, with stable targeted-cue ordering. Source filters, candidate
observations and the existing purchase-review queue remain in use. Ended lots are
excluded from Auction research but retained and labelled in the full inbox.
Seller/auction groups use explicit identities; an unknown-grouping section makes
ungrouped lots reachable without inventing an auctioneer or sale.

Price evidence distinguishes current bids, starting bids, estimates and sold
results. Only an unambiguous labelled current bid populates observed item price.
The entire monetary token must match the supported decimal/grouping syntax;
unsupported localized or malformed quotes retain their complete raw text and an
UNKNOWN amount. No locale guessing or partial-number parsing is performed.
The actual bid quotes use bare dollar signs, so their currency is **UNKNOWN**
(`XXX`), not assumed USD. Explicit currencies remain recorded and existing
unsupported-currency gates remain effective. Date-header observation time, received
time where available and import time remain distinct.

Auction start dates and relative notices remain raw evidence; none becomes a lot
deadline. Premium, platform-fee inclusion, handling, tax, shipping amount and Alaska
eligibility remain separate unknowns. No platform-wide fee rate was added. An ended
notice clears the candidate's current bid but never rewrites its linked owner's
financial record. Existing financial calculations and purchase gates are unchanged.
