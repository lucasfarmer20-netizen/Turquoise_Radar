# Phased roadmap

## 001 — Local foundation (implemented)

- FastAPI, Jinja2/HTMX, dark responsive dashboard, SQLite/SQLAlchemy, Pydantic.
- Exact curated anomalies, bounded query plan, manual pattern management and feedback.
- CSV/JSON/manual ingestion, raw preservation, deduplication, seller grouping.
- Decimal financial/scenario and maximum-bid engines with unknown-cost semantics.
- Evidence-gated melt, Alaska shipping gates, five opportunity classes.
- 25 synthetic listings, complete local pipeline tests, pinned dependencies and docs.

## 002 — Owner calibration (implemented; official research verification pending access)

- Corrected item-only commission and total-buyer-transaction processing bases,
  dated configurable category/tier fees, shipping/tax scenarios and max bids.
- Acquisition fee bases, confirmed vs estimated costs, Alaska gates and manual
  invoice allocation without invented combined-shipping savings.
- Quick Capture, editable suggestions, original paste evidence, focused review
  queue, partial evidence edits and persistent audit history.
- Manually recorded comparable sales, selected evidence confirmation, linked
  purchased-item outcomes, and source-separated actual/inferred query performance.
- Transactional SQLite v2 migrations with backups and preservation/rollback tests.
- Current eBay/Whatnot official documentation is blocked by the running cloud
  policy. Required documentation domains are saved in the draft; verify current
  authorization, rates and quota terms after access is applied.

## 003 — eBay discovery engine (implemented; API access validation pending)

Official Browse/OAuth adapter, safe fixture default, explicit sandbox/production
gates, curated query groups, bounded manual runs, correction experiments, page /
result budgets, retry handling, independent query histories and deduplication.
Discovery UI hands selected items to Phase 002 review without fabricated shipping,
resale or authentication claims. SQLite v3 preserves all older tables and records.

Next: verify current official documentation, sandbox keyset/permission and account
quotas; run one authorized small sandbox test. Production remains disabled until
final approval and explicit owner authorization. No recurring monitoring is added.

## 004 — Seller/auction optimization

Model actual combined-shipping quotations, per-order taxes/fees and marginal cost
allocation. Add multi-lot optimization only after tested fee structures exist.

## 005 — Optional vision and alerts

Use full-resolution individual images, evidence-backed observations, uncertainty
and human review. Never infer tribal authenticity, mine origin or numeric weight
from appearance. Paid calls, live spot provider, notifications and persistent
monitoring require separate scope and explicit configuration.

## Deferred until separately requested

Production scrapers, automated checkout, Telegram/Discord alerts, paid vision,
24/7 monitoring, accounts, subscriptions and deployment infrastructure.
